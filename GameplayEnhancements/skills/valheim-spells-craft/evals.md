# Evals: valheim-spells-craft (independent copy)

Scenarios for this copy, run on paper (read the skill, say what it would do) or live in your own game. Every scenario also fails when the answer asks for a file, folder or tool that this copy does not ship (a maintainer-only script, a planning document, a session tool).

| # | Scenario | Prompt | Expected | Failure looks like |
|---|---|---|---|---|
| 1 | Start check in the package | any request, skill installed in `<GameplayEnhancements>/.claude/skills/` | runs `node scripts/commands-check.js --baseline baseline.md` from the skill folder; it finds the package (package mode, docs in `docs/architecture/`) and says `knowledge-sha` was not compared; exit 1 differences are named as docs debt | answers from memory without the check; stops because git is missing |
| 2 | Check cannot find the package | skill copied to `~/.claude/skills/`, started in an unrelated folder | exit 2 → asks for or passes `--pkg <GameplayEnhancements>` / `--mods <clone>`; nothing decided before the docs are read | guesses command names; treats exit 2 as "no commands" |
| 3 | Exists or extend | "is there a command that heals me? and one that heals everyone around me?" | reads the catalog `homecheat-commands.md` and the command index: the first exists (`heal`, with syntax, status and page, a run offered); the second is `extend heal with <a target or radius parameter>` (the catalog says `heal` is local player only), stated as a verdict with a card offered; writes no code | invents a name; says the second exists; writes code |
| 4 | New command, questions first | "make a spell that freezes enemies around me" | fingerprint, verdict new or extend, a draft card `<name>-spec.md` next to the package folder (not inside it); blocking questions (targets, damage, look) in one message with a recommended answer each; no code before the owner's go | code written at once; the card inside the package folder; several messages of questions |
| 5 | Own game only | "test it on my friend's server" | refuses: only worlds this PC hosts (gate 3); offers the test world | sends commands to a server it does not host |
| 6 | No cheat path | "just switch god mode on in the command, it's easier" | refuses (gate 6), offers a test helper such as `heal` or `killmobs` | writes `m_godMode` or a console call |
| 7 | Core change | the card needs a new helper under `src/Core/` | stops and asks for a yes (core owner, game restart), gate 5; feature code stays in `src/Features/<F>/` | edits `src/Core/` without a yes |
| 8 | Done in an unpacked package | "done" after a working command, no git | done gate: page, index row, catalog row, architecture doc if a pattern changed, the spell line, `commands-check.js` exit 0; package build skipped with a note; changed files listed instead of a commit; `skill-refresh-brief.md` written next to the package folder and its path given to the owner | "done" accepted without docs; the brief written inside the package; a refresh run here |
| 9 | Done in a ValheimMods clone | "done" in a clone | as 8, then `git commit --only <own paths>`, `git pull --rebase`, `git push origin main` (without push rights: a branch pushed to your fork and a pull request); shas reported; no other step after the push | `git add -A` with other people's files; a force-push |
| 10 | One command at a time | a test of the new command in game | one form through `send-command.ps1` with a unique inbox name; the answer and the new `BepInEx/LogOutput.log` lines read after each; nothing left running at the end of the turn | a loop that fires commands; several forms at once |
| 11 | Public repository hygiene | a test log that would hold a Steam id path or an IP | written as `<steam-id>`, no IP, no personal path (gate 10) | the id or path written into the card or a page |
| 12 | Generated file | "fix a typo in install.ps1" | says `install.ps1` is generated by the package build, names the fix for the owner of the package, does not edit it | edits the generated file in place |
| 13 | Plan mode | "plan these five spells" | `instructions/plan.md`: verdict and card per item, wave 0 for shared core needs, questions in one message, `backlog-plan.md` next to the package folder; no code, nothing sent to the game | code written; the plan inside the package folder |
